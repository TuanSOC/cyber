# Threat Model

Scope: the CyberLab stack (gateway, web, API, Postgres, Redis, MinIO, and since M2 the analysis, threat-intel, AI and report workers; M8, in progress, the memory analyzer and its operator symbol tool) handling untrusted evidence for multiple organizations. This document is the honest record of what each milestone protects against and what it does not.

## Assets

- Evidence bytes and their integrity (hashes, custody chain).
- Tenant data separation (cases, evidence, members, audit).
- Sessions and credentials.
- The audit trail itself.
- (M4) Third-party API keys of each org, and what the org is investigating (the indicators it looks up).
- (M5) Investigation content disclosed to an AI provider (evidence excerpts, internal topology, file facts, case text), the org's LLM provider keys and token budget, and the integrity of what the AI analyst shows as evidence-backed.
- (M6) The integrity and authenticity of finalized reports (signed snapshots, their renditions and the report signing key), the confidentiality of what a report or export discloses (TLP, the `external` redaction), and the share-policy decisions that keep cases and evidence away from AI and TI providers.
- (M8, in progress) **Memory images**: whatever the imaged machine held (passwords and hashes, session tokens, private keys, mail, documents, chat), the command lines and shell history extracted from them, the local **symbol store** the analyzer trusts, and the fact of which kernel build an org investigates.
- (M7) **Backups** (a complete copy of every org: TLP:RED), the MinIO KMS key, the availability of data under a retention policy (nothing destroyed early, nothing held destroyed at all), legal holds, the org's search queries and its cross-case correlation graph, and the platform metrics.

## Trust boundaries

1. Browser ↔ gateway (untrusted clients, untrusted uploads).
2. Gateway ↔ API (trusted network segment; the API trusts `X-Forwarded-For` only because nothing else can reach it).
3. API ↔ data stores (API uses an RLS-bound Postgres role and a scoped MinIO user; owner/root credentials never reach it).
4. Operators (DB owner, MinIO root) — trusted administrators.
5. (M2) pcap-worker ↔ everything: the parser processes attacker-controlled captures and is treated as compromisable. It holds only a broker URL (ACL user confined to its own queue keys), runs tools as an unprivileged uid with seccomp (no inet sockets), and sits on an internal network without egress. Its output is untrusted data, validated by the trusted ingest worker before anything reaches the database.
6. (M3) static-worker ↔ everything: same boundary and same controls as the pcap-worker, with its own broker ACL user (`static`). It parses attacker-controlled files of any type (see [MALWARE_ANALYSIS.md](MALWARE_ANALYSIS.md)).
7. (M4) enrich-worker ↔ internet: the only service with a route out. It is trusted code (constant provider hostnames, org-supplied MISP URL), but everything it receives from providers is untrusted data, and everything it sends leaves the platform. It holds the sealing private keys, the app DB role and its own broker user; never the JWT secret, MinIO credentials or the app Redis. Details: [THREAT_INTEL.md](THREAT_INTEL.md).
8. (M5) analyst-worker ↔ LLM provider: the second service with a route out. Trusted code (constant vendor hosts, path allowlist, no tools for the model), but the frozen context it sends leaves the platform, and the model's answer is untrusted output shaped by untrusted evidence (prompt injection). It holds the AI sealing private keys, the app DB role and its own broker user; never the JWT secret, MinIO credentials, the app Redis or the TI private keys. Details: [AI_ANALYST.md](AI_ANALYST.md).
9. (M6) report-worker ↔ everything: the renderer lays out attacker-controlled text (from captures, samples, TI answers, AI output and analysts) with WeasyPrint, Pango, HarfBuzz and fontTools, so it is treated as compromisable, like the analyzers. It holds only a broker URL (ACL user `report`), sits on `analysis` (no egress), and renders in a uid-10004 subprocess with seccomp, rlimits and a deny-all URL fetcher. It never holds the signing key, a DB role or MinIO credentials; its output is re-hashed by the trusted ingest and is only a view of the signed snapshot. Details: [REPORTS.md](REPORTS.md#renderer).
10. (M7) retention-worker ↔ data: the only code that destroys data. Trusted code with least privilege: DB role `cyberlab_retention` (RLS-bound, DELETE on the purgeable tables only), MinIO user `cyberlab-purge` (version delete, legal hold get / put, no `PutObject`, no governance bypass, an explicit Deny on report snapshots), broker user `retention`; no JWT secret, app Redis, api MinIO user, seal or signing key, metrics token. It reads mode and values from the DB, never from a message. See [M7](#m7-platform-operations).
11. (M7) operator ↔ backups: `pnpm backup` / `pnpm restore` run with the Postgres superuser and MinIO root on the host, and the backup directory leaves the platform's control.
12. (M7) metrics scraper ↔ API: `/internal/metrics` is outside `/api`, never forwarded by the gateway, and answers only a bearer token on the `backend` network.
13. (M8) memory-worker ↔ everything: Volatility 3 parses an attacker-controlled memory image of up to 16 GiB, so the worker is treated as compromisable, like the other analyzers. Broker URL only (ACL user `memory`), `analysis` network only, tools as uid 10006 with seccomp (AF_UNIX only, no io_uring), one process per plugin, offline, read-only symbols. See [M8](#m8-memory-forensics).
14. (M8) operator ↔ `memory-symbols` ↔ Microsoft's symbol server: a trusted tool, run by hand, with its own egress network (`symbols_egress`) and write access to the symbol store only. Its inputs (a PDB GUID, a banner, an ISF file) come from images or from outside, so it validates them as untrusted.

## Known gaps (accepted for M1)

| Gap | Risk | Planned |
|---|---|---|
| No email verification, no MFA | account takeover via password reuse; fake sign-ups | later milestone |
| Members are added without consent (by email) | spam into orgs; mitigated by showing org name/role prominently and opening the user's own org by default | invitation flow later |
| Add-member responses reveal whether an email is registered | enumeration; rate limited (30/10 min per user) | invitation flow later |
| Register 409 reveals existing emails | enumeration; rate limited per IP | later |
| Storage exhaustion; uploads get a 30-day governance lock | open registration could fill MinIO with undeletable data | **mitigated in M3, not closed:** per-org quota (default 20 GiB, archived evidence counts) checked under an org row lock, and at most 5 owned orgs per user. Registration stays open, so many accounts can still claim many quotas |
| Malware scanning of uploads | stored malware is inert (never executed) | **M3:** every non-empty upload ≤ 64 MiB gets at least a ClamAV + YARA scan (`av` profile; PE/ELF get every engine). Files above 64 MiB are not scanned (for an oversized PE/ELF the skipped run is audited as `analysis.skipped`) |
| `'unsafe-inline'` scripts in CSP | weaker XSS defence | **closed in M3:** per-request nonce with `'strict-dynamic'` on every HTML page (no `'unsafe-inline'` for scripts); styles keep `'unsafe-inline'`; gateway fallback `default-src 'none'` for responses without a CSP |
| libmagic runs in the API on 8 KiB of untrusted input | parser bug in libmagic | re-deferred: M2 detects captures by magic number in pure Python; libmagic stays for the `detected_mime` metadata only |
| MinIO image is frozen `bitnamilegacy/minio` (upstream stopped community images) | no security patches | **closed in M7 (2026-11-06):** switched to the maintained fork `pgsty/silo` `RELEASE.2026-10-26T00-00-00Z`, digest-pinned with verified SLSA provenance, which fixes CVE-2025-62506 and SN-2026-015/016 ([M7](#m7-platform-operations), [runbook](../plans/reports/minio-switch-runbook-261107.md)) |
| DB owner and MinIO root are trusted | an admin can TRUNCATE/DROP TRIGGER or bypass governance | operational controls; credentials never in the API |
| RLS trusts `app.org_id` | any code that sets it from request input without `require()/org_session()` bypasses membership | AST guard test restricts where it can be set |
| Custody records download *requests*, not completed transfers; no Range/resume | aborted downloads still logged as `downloaded` | later |
| A just-rotated refresh token presented within 10 s gets `stale_refresh` (no tokens issued) instead of revoking the family | if an attacker with a stolen refresh token rotates first, the victim's refresh in that window does not trigger reuse detection; the attacker keeps the session until the victim's next refresh after the window, which then revokes it | accepted trade-off for multi-tab use |
| Metadata and custody views are not logged in the custody chain | read access to evidence details is not attributable (downloads are) | **closed in M7:** `evidence.viewed` and `evidence.custody_viewed` go to `audit_logs`, deduplicated per user, evidence and action for 15 minutes (custody still records handling only); search hits and correlation reads are not audited (decision, M7) |
| Email addresses on special-use domains (`.local`) rejected | internal-domain users cannot register | revisit with SSO |
| uvicorn runs with `--forwarded-allow-ips='*'` | if anything other than the gateway could reach the API, it could spoof client IPs and dodge per-IP rate limits | relies on the `backend` network isolation; pin to the gateway address for real deployments |
| The `api-test` container (test profile only) holds MinIO root credentials to purge locked test objects | a compromised test run could bypass governance on the dev MinIO | test profile only, never in `api`/prod |
| No backups / restore procedure | data loss | **closed in M7 (offline):** `pnpm backup` / `pnpm restore`, verified restore and a gated restore drill; online backup (PITR, replication) and off-site copies are the operator's ([DEPLOYMENT](DEPLOYMENT.md#backup-and-restore-m7)) |
| Rate limits only on specific routes | an authenticated client can flood the API | **M7:** global per-user limit (600 / min); an anonymous or gateway-level flood limit is still missing (residual) |

## M2: analysis pipeline

| Threat | Mitigation | Tested by |
|---|---|---|
| Parser exploit reads secrets | Tools run as uid 10003 without capabilities, cannot read the worker's environ/memory; broker credentials only in the root Celery process | `packages/py-worker-kit/tests/test_sandbox.py` (run in both worker images) |
| Parser exploit pivots on the network | `analysis` network is internal; seccomp denies AF_INET/AF_INET6/AF_PACKET sockets to tools; app services unresolvable | `test_isolation.py`, `test_sandbox.py` |
| Parser exploit persists into another tenant's job | kill-by-uid after every engine and job (non-dumpable / setsid escapees included), `/work` wiped before every job, container stops itself if a process survives | `test_sandbox.py` |
| Tool output tricks the root process (symlinks, FIFOs, planted names, giant lines, hostile JSON) | `dir_fd` + `O_NOFOLLOW`, regular files only, `O_EXCL` creation, bounded line/file reads, per-record error isolation | `test_sandbox.py`, `test_parsers.py`, fuzz-lite |
| Forged or replayed reports for other jobs | per-job token (sha256 stored), org taken from the job index, guarded transitions, final states immutable in the DB | `apps/api/tests/integration/test_analysis.py` |
| Hostile result stream (bombs, wrong job, extra fields, NaN, NUL, oversize) | full validation (header/trailer/sha256/caps/contract) before one all-or-nothing transaction | `test_pcap_results.py`, `test_result_stream.py` |
| Evidence swapped before analysis | worker verifies sha256 and size of the exact version; presigned GET pins the version | `test_analysis_pipeline.py` |
| One tenant starves the analyzer | per-org (5) and global (50) active caps, auto-run rate limit, queue TTL | `test_analysis.py` |

Residual risks (accepted for M2):

| Gap | Risk | Planned |
|---|---|---|
| A compromised Celery root process (not just a tool) holds the broker credentials | it could push extra or forged reports onto the ingest queue (still rejected without the target job's token) or delete queued ingest messages | per-job signed reports / separate publisher later |
| MinIO is reachable from the analysis network (presigned URLs need it) | the frozen MinIO image is exposed to a compromised worker process (tools cannot open sockets) | replace MinIO image before any real deployment |
| Tools share the container network namespace | seccomp blocks inet sockets but not unix sockets | a no-network sidecar if it becomes necessary |
| Parsers are the upstream Zeek 8 / Debian 13 builds | vulnerabilities in them are contained, not prevented | rebuild the image to update; track versions in every result |
| ET Open rules are fetched at build time, unpinned | rule drift between builds | digest recorded in every result; pinning later |
| Single analyzer FIFO with concurrency 1 | fair scheduling between orgs is approximate | per-org queues later |
| Heuristic thresholds are static, no allow-lists | false positives (e.g. legitimate updaters beaconing) | analyst feedback / allow-lists later |

## M3: static analysis and platform hardening

The static-worker reuses every M2 control above through the shared worker kit (`packages/py-worker-kit`); its tests run in both worker images. Details: [MALWARE_ANALYSIS.md](MALWARE_ANALYSIS.md).

| Threat | Mitigation | Tested by |
|---|---|---|
| A sample is executed | nothing runs the sample; engines only parse or emulate it (capa, FLOSS via vivisect) | engine tests over the synthetic set (mingw samples are compiled, never run) |
| Parser exploit in a Python probe hijacks the root process | pefile, pyelftools, yara-python and libmagic run as `python -I -s` subprocesses under uid 10003, from the root-owned read-only input dir; root only hashes the sample and accepts contract-valid records of the kinds that probe may emit | `test_engines.py`, `test_hostile_output.py` |
| Compromised emulator hides an earlier match | capa and FLOSS run last, each engine in a fresh out dir created after kill-by-uid | `test_engines.py::test_each_engine_gets_a_fresh_tool_owned_dir` |
| Memory exhaustion kills the worker | `RLIMIT_AS` per tool and `oom_score_adj=1000` on tool children; per-engine size caps (capa ≤ 16 MiB, FLOSS ≤ 8 MiB, ssdeep ≤ 4 MiB); container limit 3 GiB | `test_size_caps_skip_capa_and_floss`, fuzz-lite |
| Archive bomb or encrypted archive reported as "clean" (RT2) | explicit ClamAV file/scan/recursion/time limits with alerts, zip pre-check; any limit hit, encrypted content, capped output or missing pre-check gives `av_not_fully_scanned`, a missing DB `av_unavailable`, never a silent clean | `test_archives_are_never_silently_clean`, `test_missing_archive_precheck_fails_closed`, `test_huge_clamav_output_counts_as_not_fully_scanned` |
| Hostile YARA rule meta inflates severity | rule severity defaults to `low`; only allowlisted (rule file sha256 + rule name) rules may go higher, up to a ceiling | `test_unlisted_yara_rule_is_capped_at_low` |
| Imports or entropy alone presented as a verdict | heuristic and capability findings are capped at `medium`; only signature engines reach `high`; templates never say "malicious" | `apps/workers/static/tests/unit/test_detections.py` |
| Worker forges the sample identity | ingest rejects a `sample` line whose hashes or size differ from the evidence record (`invalid_result`); UI and report show the trusted hashes | `test_static_results.py::test_sample_of_another_file_is_refused` |
| Oversized sample | 64 MiB cap at request time (`413 sample_too_large`) | `test_analysis_static.py` |
| App role raises its own quota | 0008 column grants: the app cannot write `storage_quota_bytes` | `test_storage_quota.py` |
| Concurrent uploads overshoot the quota | authoritative check under the org row lock in the insert transaction | `test_storage_quota.py::test_concurrent_uploads_cannot_overshoot_the_quota` |
| Inline script injection (XSS) | nonce CSP with `'strict-dynamic'`; fresh nonce per request | `apps/web/e2e/csp.spec.ts` |

Residual risks (accepted for M3):

| Gap | Risk | Planned |
|---|---|---|
| ClamAV, libmagic, pefile, pyelftools, YARA, capa and FLOSS parse hostile input | a parser vulnerability is contained (uid, seccomp, rlimits, kill-by-uid, read-only rootfs, no egress), not prevented | rebuild the image to update; versions are recorded in every result |
| ClamAV DB and capa rules are as fresh as the image build | stale signatures miss newer samples | rebuild regularly; the AV DB date is shown in the UI |
| Files above 64 MiB get no AV scan | large uploads stay unscanned | revisit with a streaming scanner |
| Archives are not extracted for analysis | only ClamAV looks inside archives; PE/ELF inside a zip get no structural analysis | archive extraction later |
| Authenticode is reported as present, not validated | a forged or revoked signature looks the same as a valid one | chain validation later |
| Quota is per org, registration is open | one person with many accounts can still claim many quotas | email verification / invitations later |
| Styles keep `'unsafe-inline'` | CSS injection remains possible (no script execution) | revisit if the UI drops inline styles |

## M4: threat intelligence

The API plans lookups and seals keys; only the enrich-worker (`enrich` + `egress` networks) unseals keys and calls providers. `backend` became `internal`, so the API, ingest and data services have no route out. Details: [THREAT_INTEL.md](THREAT_INTEL.md).

| Threat | Mitigation | Tested by |
|---|---|---|
| **Key theft** from the API, a DB dump or a DB writer | sealed boxes (X25519 + HKDF + AES-GCM); the API holds only the public key and cannot import `unseal`; the private file is a compose secret of the enrich-worker only (`Settings` refuses it elsewhere); the AAD binds org, provider, kid and `key_version`, so a ciphertext cannot be moved between orgs or providers; a monotonic `key_version` trigger and no DELETE grant stop an old ciphertext from being put back | `test_ti_seal.py`, `test_ti_import_guard.py`, `test_config.py`, `test_ti_schema.py::test_a_new_key_needs_a_higher_version`, `::test_app_role_cannot_delete_provider_configs` |
| Key theft by **redirecting the MISP URL** (RT1): a compromised API or app-role DB writer points `base_url` at its own host | `base_url_norm` is in the AAD: the worker can only open a MISP key for the URL it was sealed with; a URL change through the API needs the key again (`key_required_for_url_change`) | `test_ti_seal.py::test_misp_round_trip_is_bound_to_its_url`, `test_ti_api_integrations.py` |
| Key leakage in logs, reprs, errors, audit or messages | write-only `SecretStr`; per-request `httpx.Auth` with a redacted repr (httpx masks only `Authorization`); error bodies never read; no exception chains; Celery messages carry ids only; the audit sanitizer drops `*key*` fields | `test_ti_http.py::test_key_only_in_the_auth_header_and_never_in_reprs`, `::test_error_bodies_are_never_read`, `test_ti_seal.py::test_plaintext_never_in_reprs_or_errors` |
| Stolen JWT / MinIO / app-Redis secrets through a compromised worker (RT2) | least-privilege `x-enrich-env`; `PROCESS_ROLE=enrich` refuses them; the worker cannot reach Redis, MinIO, the API or the gateway (`enrich` network) | `test_config.py`, `tests/container/test_enrich_network.py`, `scripts/check-enrich-env.mjs` (verify:prod) |
| Prod worker in dev mode (RT3) | the prod override sets `ENV=prod` and the prod image; `_prod_guards` refuse `TI_MOCK_ENABLED`, `TI_MISP_ALLOW_PRIVATE`, `TI_MISP_INSECURE_TLS` and `dev-` seal keys | `test_config.py`, verify:prod env fixture and "running, never restarted" probe |
| **SSRF** through the org's MISP URL | API: syntax only (https, no userinfo/query/fragment, allowed ports, no special-use or IPv4-like names, global literals). Worker: resolves before **every** request, every answer must be global, connects to the pinned IP with Host/SNI = hostname; no redirects; path allowlist | `test_ti_ssrf.py`, `test_ti_ssrf_resolve.py`, `test_ti_misp.py`, `test_ti_misp_worker.py` |
| An adapter sends something other than a lookup (upload, download, `/users/{key}`) | per-adapter method + host + path allowlist checked before sending; MalwareBazaar form limited to `get_info` | `test_ti_http.py::test_unlisted_paths_are_refused_before_sending`, `test_ti_provider_adapters.py` |
| **Provider response injection** (hostile JSON, control/bidi text, `javascript:` links, prompt injection aimed at M5) | strict JSON (depth, integer digits, no NaN) → `bad_json`; strict per-provider summary models ≤ 16 KiB, never the raw body; strings stripped of control/format characters; `https:` permalinks only (DB check); rendered as text | `test_ti_http.py::test_hostile_json_is_bad_json`, `test_ti_provider_fixtures.py`, `test_ti_schema.py::test_result_constraints` |
| **Decompression bombs** and oversize bodies | `Accept-Encoding: identity`; incremental inflate capped on the inflated size; 1 MiB cap (MISP 2 MiB); 20 s total timeout | `test_ti_http.py::test_gzip_bomb_is_refused_with_bounded_memory`, `::test_body_cap`, `::test_total_timeout` |
| **Quota exhaustion** (an org's key burned by big runs, or VT's silent daily quota) | per-org token bucket and daily cap on the broker, ceilings an org cannot raise; 429 cooldowns; 3 consecutive VT 429s park the provider until 00:00 UTC; the limiter fails closed; 30 run requests / 10 min per user, 3 active runs per org | `test_ti_ratelimit.py`, `test_enrich_worker.py::test_daily_quota_abandons_quota_exhausted`, `::test_consecutive_429s_are_taken_as_a_spent_daily_quota`, `::test_limiter_outage_fails_closed` |
| **Privacy leakage** (URL tokens, internal names, private IPs, emails sent to third parties) | pure normalization: global IPs only (including 6to4/NAT64/Teredo-embedded), special-use and `.arpa` names refused, URL query and fragment removed before sending or keying, emails only to MISP, paths/registry keys/JA3/certificates never; org excluded suffixes; per-provider terms acknowledgement | `test_ti_normalize.py`, `test_ti_runs.py`, `test_ti_api_runs.py` |
| **Cross-org cache inference** (learning what another org investigates from cache hits or results) | the cache is the org's own history (RLS plus an explicit org filter); no shared cache; per-org rate-limit buckets and keys | `test_ti_cache.py`, `test_ti_schema.py::test_tenant_tables_are_isolated`, `test_idor_routes.py`, `test_rls_coverage.py` |
| **Worker starvation** (one org's 200-IOC VT run holds the single worker for 50 min, RT6) | ≤ 20 s time slices (asyncio-enforced), re-queue at the tail, `waiting` + `resume_at` instead of sleeping; DB lease against duplicates; 30 min deadline; reaper fallback | `test_enrich_worker.py::test_slice_budget_republishes_to_the_tail`, `::test_redelivery_and_concurrent_duplicates_make_no_extra_calls`, `::test_deadline_ends_partial`, `::test_fallback_reaper` |
| Forged or cross-org `ti.*` messages | messages carry ids only; the org must match `ti_run_index`; `ti.verify` re-reads the config in the org's tenant session | `test_enrich_worker.py::test_org_mismatch_and_bad_messages_are_dropped` |
| A working key disabled by a resource-level 403 (RT23) | 401/403 → inline verify; only a failed verify marks the key invalid | `test_enrich_worker.py::test_403_with_passing_verify_stays_valid` |
| Analyzers reach the enrich queue or the internet | broker ACL: `pcap` / `static` cannot touch `enrich*`; `enrich` cannot touch `trusted.*` / `ingest*`; analyzers stay on `analysis` (internal) | `test_enrich_acl.py`, `tests/container/test_egress.py`, worker-kit `test_isolation.py` |
| Reputation read as our verdict | attributed templates, neutral chips, no TI-derived findings or severity changes in M4 | `apps/web/lib/ti-wording.test.ts` |

Residual risks (accepted for M4):

| Gap | Risk | Planned |
|---|---|---|
| **Unrestricted egress** of the enrich-worker (no proxy or hostname allowlist) | a compromised worker can send anything it can read (keys it unseals, DB rows) anywhere | egress proxy with a hostname allowlist later |
| The enrich-worker uses the **full app DB role** (RT17) | a compromised worker can read every tenant's rows (it sets the org context itself, as the trusted ingest does) | dedicated enrich role (needs bootstrapping on existing volumes) later |

| **Third-party disclosure** of investigated IOCs | every lookup tells the provider what the org investigates; hash lookups reveal that the org holds a file (RT28) | opt-in per provider with a terms acknowledgement; no auto-enrichment |

## M5: AI analyst and prompt injection

The API builds and freezes the context in the requester's RLS session and never calls a provider; only the analyst-worker (`enrich` + `egress` networks) unseals AI keys and calls Anthropic or Gemini. | **A purge is not retroactive in old backups** | data purged by policy survives in every older backup; restoring one brings it back | backup retention is the operator's policy; run the retention sweep again after restoring an older backup (idempotent) |
| **The KMS key sits on the host** (RT7) | SSE-S3 protects against loss of the volume or disk only, not against a host compromise; losing or changing the key makes every SSE object **and MinIO's own IAM and config** unreadable | an encrypted copy of `.secrets/minio_kms_key` with the other secrets; restore refuses a different key; KMS / HSM later |
| **SSE-S3 covers new objects only** | objects written before M7 stay plaintext on disk and in backups until rewritten | documented; no rewrite tool in M7 |
| **The api's M1 evidence delete grant** (RT5) | the api MinIO user keeps `DeleteObject` / `DeleteObjectVersion` on the evidence buckets (cleanup of a failed upload), so once a version's GOVERNANCE lock expires (`EVIDENCE_LOCK_DAYS`, 30) a compromised API can delete an **unheld** version **without a tombstone**. Narrowed in phase 11: case and org holds are both mirrored as S3 legal holds (the api cannot clear one), and the api's own cleanup path refuses under any protecting hold or for a recorded key (`integration/test_evidence.py::test_db_failure_under_a_legal_hold_keeps_the_version`, `unit/test_evidence_delete_paths.py`, `integration/test_retention_objects.py::test_an_org_hold_is_mirrored_on_every_evidence_version`). Left: unheld expired versions, and the sync window below | `reconcile_orphans.py` reports `missing_unexplained` and `restore_verify --objects` fails on a pinned version missing without a tombstone; staging uploads under a prefix (RT35) later |
| **A compromised retention worker** | it can clear an S3 legal hold (it owns `PutObjectLegalHold`) and then delete expired versions in its categories; it cannot touch metadata, hashes, custody, audit or locked versions | least privilege above; every purge leaves a tombstone, custody event, audit row and run item |
| **S3 legal hold sync window** | between a hold's commit and the worker's sync (`s3_sync: pending`), the S3 hold is not yet ON; the DB selector already excludes the data and the api's own cleanup path checks the DB, but a compromised API holding the expired-lock delete grant does not. An org hold over a large org takes several syncs (5 000 versions inspected, 500 changed per call, shared by the passes; resumed from a keyset cursor), and a release over more than 5 000 versions clears S3 holds over several syncs, also resumed (fails closed meanwhile: the purge skips a held version) | `retention.sync_holds` is published at once for case and org holds and every run and sweep syncs again; oldest versions (whose lock expires first) go first |
| **Search under RLS does not use the trigram / FTS indexes** | `@@`, `%` and `ILIKE` are not `LEAKPROOF`, so every non-exact search is a per-org scan; a large org approaches the 3 s timeout (`partial` answers) | accepted pending the phase-11 performance numbers; LEAKPROOF wrappers or a `SECURITY DEFINER` search function (0015) is the fix; OpenSearch criteria in ARCHITECTURE |
| **Search and correlation reads are not audited** (RT34) | an insider's pivots across cases leave no trail beyond the evidence views they open | decision: queries can be sensitive, a hashed query is dictionary-reversible; results are RLS-bound |
| **No anonymous or gateway-level flood limit** (RT14) | unauthenticated or bogus-cookie floods reach the API (a cheap 401) and the per-route limits | Caddy has none without a plugin; put a rate-limiting proxy or WAF in front of a real deployment |
| **MinIO image `bitnamilegacy/minio:2025.5.24` was unpatched** (closed 2026-11-06) | it predated **CVE-2025-62506** (IAM privilege escalation, CVSS 8.1) and carried **SN-2026-015/016**, a GOVERNANCE retention bypass through `PutObjectRetention` and in-place version overwrites | **closed:** the default is now the local wrapper `localhost/cyberlab/silo:RELEASE.2026-10-26T00-00-00Z`, built `FROM pgsty/silo@sha256:7bb2aff6b89efe1cb1303c10fc21d579447434ed06649ac9ec05a5e2dbf30ad7` (provenance: `gh attestation verify oci://index.docker.io/pgsty/silo@sha256:7bb2aff6… --repo pgsty/silo --signer-workflow pgsty/silo/.github/workflows/docker-release.yml --source-ref refs/tags/RELEASE.2026-10-26T00-00-00Z --deny-self-hosted-runners`), read-only, `cap_drop: ALL`, uid 1001 / gid 0. Gates passed: backup, isolated conformance, restore drill, then the conformance suite, the storage and evidence suites and a bucket-creation probe on the live store ([runbook](../plans/reports/minio-switch-runbook-261107.md)). Remaining: the `mc` client stays `bitnamilegacy/minio-client` (minio-init only, never exposed); a rollback is a full restore (no in-place downgrade); SN-2026-015/016 is fixed upstream but not reproduced by the suite |
| **No live AI or TI run recorded** | the §14 AI citation accuracy and IOC enrichment numbers exist only for offline / synthetic providers; model ids, prices and real provider behaviour are unverified | `scripts/live_run.mjs` exists (opt-in, budget-capped, never in the gate); running it needs the user's keys and budget |
| **Runtime metrics come from replays of the synthetic dataset** | failure rate and latency under real workloads are unknown until production traffic exists | the metrics endpoint and the org page report real runs as they happen |

## M8: memory forensics

**In progress.** Phase 1 (contracts, migration 0016, compose services, stubs) is committed and untested in a container; every control below marked *pending* is planned, not built, and every "Tested by" entry that names a phase is a planned test. Design: [MEMORY_ANALYSIS.md](MEMORY_ANALYSIS.md); runbook: [DEPLOYMENT.md](DEPLOYMENT.md#memory-forensics-m8). Red-team findings RT1–RT36 are in the [plan](../plans/261107-0300-cyberlab-m8-memory-forensics/plan.md#red-team-changes-2026-11-07).

**New assets and boundaries:** memory images and their extracted text, the symbol store; boundaries 13 and 14 above.

| Threat | Mitigation | Tested by |
|---|---|---|
| **Parser exploit in Volatility** (a crafted image takes over a plugin) | the M2 / M3 container isolation (`analysis` only, broker URL only, read-only rootfs, caps, fail-closed restart; built); one process per plugin as uid 10006 with seccomp, rlimits and kill-by-uid, a fresh out dir and cache per plugin, so one compromised plugin cannot rewrite another's output; root never parses image bytes, reads tool output with bounded readers and validates every row; the trusted ingest re-validates the whole stream (pending phases 2, 6) | `apps/workers/memory/tests/test_isolation.py` (written, phase 1); runner and hostile-output tests (phase 2); memory ingest tests (phase 6) |
| **Denial of service by image** (huge, smeared, looping or decompression-bomb input) | per-plugin and job timeouts, `RLIMIT_AS` 2.5 GiB and `RLIMIT_FSIZE` 512 MiB per plugin, `mem_limit 3g`, record caps with `truncated` flags and a streaming visitor that stops at the cap; compressed and archive magic refused before any probe (RT19); free-space check before the download; at most 1 active memory job per org, 2 overall | caps in `test_memory_contract.py` (host-run); probe smoke on a sparse 8 GiB file and fuzz-lite (phases 2, 11) |
| **Symbol poisoning** (a tampered or hostile ISF makes the analyzer misreport) | the store is read-only in the worker; only the operator tool writes it, through a temp dir and a verified atomic move; every file's sha256 is in `manifest.json` and re-checked before use (`symbols_corrupt`); ISFs are validated with `jsonschema` in a child process with `RLIMIT_AS` and a timeout; zip members checked for traversal, symlinks, type, count and size; the result records the loaded ISF's sha256 (pending phase 5) | `SymbolManifestV1` path rules (`hostile/manifest_dotdot.json`, phase 1); `test_symbols_{store,manifest,import}.py`, `test_symbols_tool.py` (phase 5) |
| **Hostile GUID or banner relayed to the operator** (an image steers what the tool fetches, or a pasted command injects into the operator's shell) | strict validation of the identity in the contract (kernel PDB allow-list, 32 hex digits, age range, printable banner ≤ 512); the UI builds a command only for Windows, from the validated fields; a Linux banner is shown as inert text, never inside a command (RT12); the tool re-validates, builds the URL from validated parts only, follows at most 3 HTTPS redirects to hosts matching a recorded suffix allow-list, never an IP literal, ≤ 128 MiB, and checks the converted ISF's GUID and age against the request (RT11) | `hostile/{bad_guid,non_kernel_pdb,banner_control_chars}.ndjson` (phase 1); `test_symbols_fetch.py` against a local HTTPS mock (phase 5); UI tests (phase 9) |
| **Network access at analysis time** (Volatility's PDB downloader over plain HTTP, remote ISF, `smb://`) | the worker is on the internal `analysis` network; Volatility set offline in code (`OFFLINE`, `REMOTE_ISF_URL = None`); seccomp allows AF_UNIX sockets only; a PEP 578 audit hook refuses and counts socket, urllib, subprocess and exec events; `pysmb` not installed; the symbol path list has no writable entry (RT2, RT7) | `test_offline.py`, `test_audit_hook.py`, `test_symbol_paths.py`, probe smoke (phase 2); env and network checks (phase 11) |
| **Exposure before restriction** (an automatic scan, AI or TI reads a memory image before it is marked sensitive) | a `kind=memory` upload gets no automatic analysis at all (built, RT3); the TLP:RED default is applied in the upload transaction (pending phases 6, 8), or at the first memory job for other uploads, and the run dialog says earlier jobs are covered only from then on | `test_m8_foundation.py` (written, phase 1); `test_memory_sensitivity.py` (phase 8) |
| **Plugin or code loading** (a plugin path, config file or writable site-packages lets the image run other code) | the probe uses library mode, never the CLI: no `-p`, no `vol.json`, a fixed per-plugin configuration; site-packages root-owned; `HOME` / `XDG_CONFIG_HOME` = `/nonexistent`; the plugin enum is the only thing that can be requested, and the result header is refused for any other plugin | `test_skeleton.py`, `hostile/unknown_plugin.ndjson` (phase 1); `test_plugin_allowlist.py` (phase 2) |

| **Forged or replayed results** (a compromised worker writes another job's rows or inflates them) | the M2 per-job ingest token and org from the job index; the header must name the job and the profile's allow-list; the image line must match the evidence sha256 and size; caps, trailer hash and framing bounds checked before any write; a replay result says `engine: replay` and the replay engine is refused outside `TEST_PROFILE=1` | `hostile/{wrong_job,after_trailer,no_trailer,extra_field,verdict_severity}.ndjson` (phase 1); memory ingest tests (phase 6) |
