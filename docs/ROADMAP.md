# Roadmap

| Milestone | Scope | Notes |
|---|---|---|
| **M1 — Foundation** ✅ | Monorepo, Compose, auth, orgs/RBAC, investigations, evidence with integrity + custody, audit, dashboard shell | |
| **M2 — PCAP Analyzer** ✅ | Isolated pcap-worker (Zeek 8, TShark, Suricata 7 + ET Open) behind versioned job/result contracts; trusted ingest into tenant tables; flows, DNS/HTTP/TLS, alerts, heuristic findings (beaconing, scans, DNS anomalies, suspicious traffic), IOCs, timeline; analyzer UI; synthetic labeled dataset with precision/recall (1.0 / 1.0 on a **synthetic dataset** built with the detectors, not real-world quality) | Deferred from M2: OpenSearch (Postgres suffices at this scale), nonce CSP and storage quotas (→ M3), JA4, per-org fair scheduling |
| **M3 — Malware static analysis** ✅ | Isolated static-worker (ClamAV, YARA, pefile / pyelftools, strings, capa, FLOSS; never executes samples) on the M2 job pipeline with a `static.v1` contract; hashes, PE/ELF metadata, sections, imports/exports, resources, strings, entropy; verdict-free findings (suspicious API sets, packer, PE anomalies, signatures, capabilities), IOCs; ClamAV + YARA scan of every upload ≤ 64 MiB; Malware Lab UI, JSON + printable report; synthetic sample set with precision/recall (1.0 / 1.0 on the **synthetic** set) and fuzz-lite. Platform: nonce CSP, per-org storage quotas, owned-org limit. See [MALWARE_ANALYSIS.md](MALWARE_ANALYSIS.md) | Deferred from M3: Mach-O, Detect It Easy, Authenticode chain validation, a persisted `reports` table (done in M6; the static JSON report stays on demand), archive extraction for analysis |
| **M4 — Threat intelligence** ✅ | Lookup-only IOC enrichment from VirusTotal, AbuseIPDB, URLhaus, MalwareBazaar, AlienVault OTX and MISP through a least-privilege enrich-worker, the only service with egress (`backend` is now internal); sealed per-org API keys (the API encrypts only, MISP keys bound to their URL), write-only in the UI; normalization that never sends private IPs, internal names, URL queries or emails (except to MISP); per-org append-only history used as the cache; broker-side rate limits, time-sliced runs with waiting/resume and deadlines; SSRF-hardened MISP client; offline pinned ATT&CK index with labels on capabilities and findings; verdict-free, source-attributed UI (Integrations page, Enrich IOCs, lookup page, IOC history). See [THREAT_INTEL.md](THREAT_INTEL.md) | Reputation is never sole evidence. Deferred from M4: auto-enrichment after ingest and investigation-scope runs (need a consent model, → M5/M6), a dedicated enrich DB role, an egress proxy with a hostname allowlist, a TLP model on evidence and cases (done in M6), live verification of provider quotas, a batch re-seal script, `ti_results` retention, enrich-worker scale-out, feeds (TAXII, MISP sync), ICS/Mobile ATT&CK |
| **M5 — AI Analyst** ✅ | Evidence-cited AI analysis (Anthropic Claude, Google Gemini, a dev mock) through a least-privilege analyst-worker, the second service with egress, and **no tools for the model**; the API builds and freezes the context (deterministic selection and caps, short labels, internal IPs / hosts / users pseudonymized, URLs defanged, query values replaced, spotlighted untrusted evidence); structured output `ai.v1` separating observed / interpretation / hypotheses / confidence / next steps / limitations; a deterministic verifier re-queries every cited row in scope, checks quotes (minimum length, anchored claims) and ATT&CK ids, flags verdict wording, command-like steps, external URLs and canary leaks; explain finding / alert, summarize capture, explain static, IOC correlation, ATT&CK mapping and incident summary (map-reduce with timeline and recommendations); sealed write-only per-org keys in their own domain; opt-in per org with privacy and terms acknowledgements, Gemini paid tier only; daily budgets, per-call and per-incident caps, rate limits, typed run statuses; offline evaluation with Fake / Hostile / Replay providers and P1–P8 adversarial twins. See [AI_ANALYST.md](AI_ANALYST.md) | Outputs are observations to verify, never verdicts or actions; integrity attacks are detected, not prevented. Deferred from M5: model tools, agents, chat, auto-run after ingest, provider-native citations, Batch / Files APIs, local or OpenAI-compatible models, Covered Models, ZDR contracting, a TLP / "do not send to AI" flag (done in M6), retention and purge of `ai_*` rows, fine-tuning / embeddings / RAG, analyst feedback, a dedicated analyst DB role, an egress proxy, KMS/HSM key custody, per-user keys, refusal fallbacks, a batch re-seal tool, live verification of model ids, prices and quality (no live run recorded) |
| **M6 — Reports and case management** ✅ (done 2026-11-06; the `verify:prod` gate passed in segments, not in one uninterrupted run: dev phase in gate run vp8, prod phase with the fixed gate in its own compose project) | Case management: versioned analyst notes, IOC collections (normalized by the M4 normalizer, joined to TI history; CSV formula-safe / JSON / STIX 2.1 exports with the TLP 2.0 marking), status reasons and an append-only history, analyst-confirmed ATT&CK mapping with suggestions (capa, findings, verified AI) and a tactic matrix, timeline `note` / `status` kinds and CSV / JSON export. TLP 2.0 on cases and reports (downgrade needs `org.update` and an acknowledgement, re-checked at finalize) and the "do not send to AI / TI" share policy on cases and evidence (TLP:RED implies both), enforced in the API and re-checked by the analyst and enrich workers. Reports: drafts finalized into immutable versions; snapshot `cyberlab.report.v1` (canonical JSON, sha256) signed with Ed25519 and stored object-locked; `[Cn]` citations re-queried in scope with field hashes and "cited by"; verified AI claims only; `internal` / `external` profiles with one report-level pseudonym map; offline verification (`scripts/verify_report.py`, public keys route). An isolated WeasyPrint report-worker (no egress, no DB, seccomp, rlimits, deny-all fetcher) renders PDF/A-3a (structurally checked, veraPDF not gating) with the signed snapshot embedded, HTML and Markdown, byte-reproducibly, within a calibrated render budget. See [REPORTS.md](REPORTS.md) | The signed snapshot is the record of truth; renditions are views of it. Deferred from M6: DOCX export, a "Cited by" panel on rows in the web app (the route exists), PAdES / pyHanko signatures, RFC 3161 timestamps, KMS / HSM key custody and per-user signing keys, report templates per org, images and charts, rich text / Markdown in analyst text, sharing reports outside the platform, approval workflows and multi-signer reviews, TAXII / MISP push of collections, org-wide IOC watchlists, retention and purge of reports and notes, veraPDF in CI and PDF/UA-1 claims, per-case access control (viewers can download any report, audited), case scope for manual TI lookups, a stored external pseudonym map, CJK fonts |
| **M7 — Platform operations and correlation** ✅ (done 2026-11-06; the `verify:prod` gate passed in segments, the restore drill as its own last step) | Offline, quiesced backup and restore of Postgres and the MinIO volume (version ids, object lock and legal holds kept) with a three-phase `restore_verify` and an automated restore drill; per-org data retention (TI history, AI runs, closed-case bytes and bulk rows, renditions) with floors, a 7-day delay on every loosening, dry run by default, legal holds mirrored to S3, a least-privilege retention worker and tombstones (`410 evidence_purged`); deterministic in-org correlation ("also seen in", lookup, related cases) on M6 IOC keys; org-wide search on Postgres FTS and trigram (POST, never logged); runtime job metrics from DB triggers (`/internal/metrics`, never routed by the gateway, and an org page); a global per-user rate limit, audited evidence views, a declared-vs-detected type flag, SSE-S3 at rest, an object-store conformance suite; [SANDBOX_SECURITY.md](SANDBOX_SECURITY.md) and the frozen `dynamic.v1` contract (dynamic analysis stays disabled). See [ARCHITECTURE.md](ARCHITECTURE.md#platform-operations-m7), [DEPLOYMENT.md](DEPLOYMENT.md#backup-and-restore-m7) | Gate passed in segments (2026-11-06; numbers in the M7 plan's Closure). The object store switched to the maintained fork `pgsty/silo` (digest-pinned local wrapper; CVE-2025-62506 and SN-2026-015/016 of the former bitnami image closed, THREAT_MODEL). Deferred from M7: online backup / PITR and replication, in-script backup encryption, OpenSearch (revisit criteria in ARCHITECTURE), search index use under RLS (LEAKPROOF wrappers or a definer function, 0015), purging notes, collections, findings, IOCs, snapshots or audit, per-case retention, an anonymous / gateway flood limit, an org upload reject list, removing the api's evidence delete grant, a Prometheus / Grafana service, live AI and TI runs (no key or budget yet) |
| **M8 — Memory forensics** (in progress: phases 1–3 and 5–9 committed on `feat/m8-memory-forensics`, docs drafted (phase 10), security-review fixes applied, M7 merged in; untested in Docker; the detector metrics and the gate pending) | Volatility 3 (pinned 2.28.2) as a third untrusted analyzer on the M2 / M3 pattern: an isolated, network-less memory-worker runs an allow-listed set of triage plugins (Windows and Linux, `triage` / `full`), one sandboxed process each, offline against a read-only symbol store; a versioned `memory.v1` contract; trusted ingest into the memory tables (`0016`) plus the shared findings, IOCs and timeline; verdict-free triage heuristics (never above `medium`) with a secret masker; a trusted operator tool `memory-symbols` (own egress network) that fetches Windows kernel PDBs over verified HTTPS on request and imports operator ISFs; a missing symbol becomes a diagnostic result; memory images TLP:RED by default (AI / TI excluded, admin release, reports only at TLP:RED); never automatic. See [MEMORY_ANALYSIS.md](MEMORY_ANALYSIS.md) | **Decision pending (user, not legal advice):** whether to publish `apps/workers/memory/` under the Volatility Software License before the platform is offered to anyone else, including as a hosted service (the adapter is a VSL "Addition"; the repository has no licence file yet; `apps/workers/memory/NOTICE.md`). Pending in M8: the synthetic Linux image go / no-go, the detector metrics (phase 11) |
| **M9 — Disk forensics** (in progress: phases 1, 2 and 5–9 committed on `feat/m9-disk-forensics`, phases 10–12 being written; Plaso (phase 3), the image generator (phase 4), the metrics and the gate (phase 13) pending; nothing run in Docker yet) | The Sleuth Kit through pytsk3 (TSK 4.15.0 embedded, library mode) and libewf as a fourth untrusted analyzer on the M2 / M3 / M8 pattern: ordered segment sets of raw, split raw or E01 evidence (8 GiB per segment, 16 GiB per set by default), one sandboxed process per stage (killed and sealed after each, a write watchdog, a deadline budget), explicit volume and file-system families only (NTFS, FAT / exFAT, ext; BitLocker, LUKS, APFS, LVM, HFS+, ISO refused by signature first), a file listing with deleted names, orphans, NTFS streams and hard links, hashes within budgets, offline known-file hash sets (operator-imported NSRL RDSv3 or plain lists, `network_mode: none` tool), YARA (M3 rules) on PE files, Plaso on a bounded extracted artifact tree (never the image), a never-collected list of credential files applied to every name of an inode, verdict-free findings (never above `medium` except YARA), a dedicated trusted disk ingest worker, a merged timeline, interop exports for `mactime`, Timesketch and Autopsy's hash-set import, single-file export to derived evidence; TLP:RED by default with batch release; never automatic.
