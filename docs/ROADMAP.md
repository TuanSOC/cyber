# Roadmap

| Milestone | Scope | Notes |
|---|---|---|
| **M1 — Foundation** ✅ | Monorepo, Compose, auth, orgs/RBAC, investigations, evidence with integrity + custody, audit, dashboard shell | this release |
| **M2 — PCAP Analyzer** ✅ | Isolated pcap-worker (Zeek 8, TShark, Suricata 7 + ET Open) behind versioned job/result contracts; trusted ingest into tenant tables; flows, DNS/HTTP/TLS, alerts, heuristic findings (beaconing, scans, DNS anomalies, suspicious traffic), IOCs, timeline; analyzer UI; synthetic labeled dataset with precision/recall | Deferred from M2: OpenSearch (Postgres suffices at this scale), nonce CSP and storage quotas (→ M3), JA4, per-org fair scheduling |
| **M3 — Malware static analysis** ✅ | Isolated static-worker (ClamAV, YARA, pefile / pyelftools, strings, capa, FLOSS; never executes samples) on the M2 job pipeline with a `static.v1` contract; hashes, PE/ELF metadata, sections, imports/exports, resources, strings, entropy; verdict-free findings (suspicious API sets, packer, PE anomalies, signatures, capabilities), IOCs; ClamAV + YARA scan of every upload ≤ 64 MiB; Malware Lab UI, JSON + printable report; synthetic sample set with precision/recall and fuzz-lite. Platform: nonce CSP, per-org storage quotas, owned-org limit. See [MALWARE_ANALYSIS.md](MALWARE_ANALYSIS.md) | Deferred from M3: Mach-O, Detect It Easy, Authenticode chain validation, a persisted `reports` table (done in M6; the static JSON report stays on demand), archive extraction for analysis |
| **M4 — Threat intelligence** ✅ | Lookup-only IOC enrichment from VirusTotal, AbuseIPDB, URLhaus, MalwareBazaar, AlienVault OTX and MISP through a least-privilege enrich-worker, the only service with egress (`backend` is now internal); sealed per-org API keys (the API encrypts only, MISP keys bound to their URL), write-only in the UI; normalization that never sends private IPs, internal names, URL queries or emails (except to MISP); per-org append-only history used as the cache; broker-side rate limits, time-sliced runs with waiting/resume and deadlines; SSRF-hardened MISP client; offline pinned ATT&CK index with labels on capabilities and findings; verdict-free, source-attributed UI (Integrations page, Enrich IOCs, lookup page, IOC history). See [THREAT_INTEL.md](THREAT_INTEL.md) | Reputation is never sole evidence. Deferred from M4: auto-enrichment after ingest and investigation-scope runs (need a consent model, → M5/M6), a dedicated enrich DB role, an egress proxy with a hostname allowlist, a TLP model on evidence and cases (done in M6), live verification of provider quotas, a batch re-seal script, `ti_results` retention, enrich-worker scale-out, feeds (TAXII, MISP sync), ICS/Mobile ATT&CK |
| **M5 — AI Analyst** ✅ | Evidence-cited AI analysis (Anthropic Claude, Google Gemini, a dev mock) through a least-privilege analyst-worker, the second service with egress, and **no tools for the model**; the API builds and freezes the context (deterministic selection and caps, short labels, internal IPs / hosts / users pseudonymized, URLs defanged, query values replaced, spotlighted untrusted evidence); structured output `ai.v1` separating observed / interpretation / hypotheses / confidence / next steps / limitations; a deterministic verifier re-queries every cited row in scope, checks quotes (minimum length, anchored claims) and ATT&CK ids, flags verdict wording, command-like steps, external URLs and canary leaks; explain finding / alert, summarize capture, explain static, IOC correlation, ATT&CK mapping and incident summary (map-reduce with timeline and recommendations); sealed write-only per-org keys in their own domain; opt-in per org with privacy and terms acknowledgements, Gemini paid tier only; daily budgets, per-call and per-incident caps, rate limits, typed run statuses; offline evaluation with Fake / Hostile / Replay providers and P1–P8 adversarial twins. See [AI_ANALYST.md](AI_ANALYST.md) | Outputs are observations to verify, never verdicts or actions; integrity attacks are detected, not prevented. Deferred from M5: model tools, agents, chat, auto-run after ingest, provider-native citations, Batch / Files APIs, local or OpenAI-compatible models, Covered Models, ZDR contracting, a TLP / "do not send to AI" flag (done in M6), retention and purge of `ai_*` rows, fine-tuning / embeddings / RAG, analyst feedback, a dedicated analyst DB role, an egress proxy, KMS/HSM key custody, per-user keys, refusal fallbacks, a batch re-seal tool, live verification of model ids, prices and quality (no live run recorded) |
| **M6 — Reports and case management** ✅ | Case management: versioned analyst notes, IOC collections (normalized by the M4 normalizer, joined to TI history; CSV formula-safe / JSON / STIX 2.1 exports with the TLP 2.0 marking), status reasons and an append-only history, analyst-confirmed ATT&CK mapping with suggestions (capa, findings, verified AI) and a tactic matrix, timeline `note` / `status` kinds and CSV / JSON export. TLP 2.0 on cases and reports (downgrade needs `org.update` and an acknowledgement, re-checked at finalize) and the "do not send to AI / TI" share policy on cases and evidence (TLP:RED implies both), enforced in the API and re-checked by the analyst and enrich workers. Reports: drafts finalized into immutable versions; snapshot `cyberlab.report.v1` (canonical JSON, sha256) signed with Ed25519 and stored object-locked; `[Cn]` citations re-queried in scope with field hashes and "cited by"; verified AI claims only; `internal` / `external` profiles with one report-level pseudonym map; offline verification (`scripts/verify_report.py`, public keys route). An isolated WeasyPrint report-worker (no egress, no DB, seccomp, rlimits, deny-all fetcher) renders PDF/A-3a with the signed snapshot embedded, HTML and Markdown, byte-reproducibly, within a calibrated render budget. See [REPORTS.md](REPORTS.md) | The signed snapshot is the record of truth; renditions are views of it. Deferred from M6: DOCX export, a "Cited by" panel on rows in the web app (the route exists), PAdES / pyHanko signatures, RFC 3161 timestamps, KMS / HSM key custody and per-user signing keys, report templates per org, images and charts, rich text / Markdown in analyst text, sharing reports outside the platform, approval workflows and multi-signer reviews, TAXII / MISP push of collections, org-wide IOC watchlists, retention and purge of reports and notes, veraPDF in CI and PDF/UA-1 claims, per-case access control (viewers can download any report, audited), case scope for manual TI lookups, a stored external pseudonym map, CJK fonts |
| Later | Memory forensics (Volatility 3), disk forensics (TSK, Plaso), reverse engineering (Ghidra headless, radare2), invitations/MFA/SSO, backups, retention policies | |
| Gated | Dynamic analysis (CAPE) in disposable, network-isolated VMs | not enabled until isolation is tested |
